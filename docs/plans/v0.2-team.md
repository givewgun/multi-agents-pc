# tandem v0.2 — a real team, not a manager and a worker

Status: **built** 2026-11-23 (decisions: hooks yes, Notion later). Draft (Claude) → critique (Gemini) → build split → dual review (Gemini found 14 issues, all fixed; regression tests in `test/v02-review.test.js`).

## Problems (from the user)
1. Claude acts as the boss and Gemini as the worker. Starting from Gemini should work the same way.
2. The dashboard shows ~99% "offloaded to Gemini". Claude's own interactive work isn't logged, so Claude looks like a mask over Gemini.
3. You can't see the conversations: headless calls don't appear in the Antigravity app, and the prompts and replies aren't stored.
4. Model choice feels automatic. The user wants to pick, on either side.
5. "Orchestrator" is confusing: it's a Gemini model (Neon plans, Hydrogen executes), not the team lead.

## Principles
- **Lead = whichever agent the user is talking to.** The lead owns the plan, the decisions and the final answer. The other agent is the **partner**. Roles swap with the entry point; the protocol is identical on both sides.
- **Collaborate, don't just offload.** Work goes to whoever is better or cheaper at it, plus patterns where both contribute (plan critique, dual review, split by strength). A good session shows *both* agents doing real work.
- **The user overrides everything.** A model or agent the user names is used as-is. Routing only fills gaps.
- **Everything visible.** Every exchange can be read (locally) and reopened in its native app.

## Workstreams

### A. Symmetric protocol (lead / partner)
- Rewrite `templates/AGENTS.md` role-neutral: strengths table, lead/partner rules, the 4 collaboration patterns:
  1. **plan-critique:** the lead drafts, the partner critiques, the lead merges.
  2. **split:** the lead assigns slices by strength and integrates the results.
  3. **dual-review:** both review the diff; disagreements get a closer look.
  4. **second-opinion:** after 2 failed attempts, ask the partner for hypotheses.
- Mirrored skills, lean (loaded on demand):
  - Claude: `/gemini` (ask the partner) + `/pair` (the 4 patterns).
  - Antigravity: `ask-claude` + `pair` skills (`skills/<name>/SKILL.md`, YAML `name`/`description`), plus the existing `model_decision` rule for automatic escalation. *Gemini drafts its own skills in its native format.*
- **Antigravity side ships as a plugin**, `~/.gemini/config/plugins/tandem/`: `mcp_config.json` + `hooks.json` + `rules/` + `skills/` in one toggleable unit (research §6). Replaces the loose files `init --global` writes today.
- Router becomes lead-aware: `route(task, budget, lead)`. If the best agent is the lead itself, return "do it yourself" (no call, no overhead). MCP sets the lead from `--expose` (exposing gemini ⇒ Claude is the lead).
- Keep one always-on rule per side ≤10 lines; the rest lives in skills.

### B. Manual model choice (both directions)
- Already possible: `--model` on the CLI, the `model` argument on MCP tools.
- Add persistent preferences: `tandem prefer gemini neon-high`, `tandem prefer claude opus` (defaults), and per-category pins: `tandem pin review claude:opus`. The router honours pins before rules.
- Skills say it explicitly: "If the user names a model or agent, use exactly that."
- `tandem models` lists aliases → real slugs for both sides.

### C. Visibility
- **Read native transcripts, don't copy them.** Both agents already save every headless call:
  - Claude: `~/.claude/projects/<cwd-slug>/<session>.jsonl`, reopenable with `claude --resume <id>`.
  - Gemini: `~/.gemini/antigravity-cli/brain/<conversation>/.system_generated/logs/transcript.jsonl` (verified; per-step `content`, `tool_calls`, `input_tokens`, `output_tokens`, `cache_read_tokens`), reopenable with `agy --conversation <id>`.

  tandem stores only the session id (already in the ledger). `tandem show <ledger-id|last>` renders the exchange from the native file. No duplicate prompt storage; privacy stays as in ADR 0006.
- **Threads:** calls made for one task share a `thread` id (the lead passes it; MCP tools accept it), so a plan-critique or dual review reads as one conversation.
- **Antigravity app:** CLI, app and IDE keep separate stores (research §1), so headless calls don't appear in the app feed. Live test with the user: `agy -p … --project <app project id>`. If it shows up in the app, tandem uses a "tandem" project; if not, tandem's view plus `agy --conversation` is the way.
- **Dashboard:** a "Conversations" tab (thread list → message bubbles Claude ↔ Gemini with model, tokens, time, "open" command). Built by Gemini; the server adds `/api/thread/:id` reading native transcripts.

### D. Honest accounting: who did the work
- Log the lead's own work:
  - **Claude Code `Stop` hook** (payload: `session_id`, `transcript_path`) → `tandem hook claude` reads the new per-message `usage` since its last offset → ledger record `to: claude, from: user, tag: interactive`.
  - **Antigravity `Stop` hook** (payload: `conversationId`, `modelName`, `transcriptPath`; research §3) → `tandem hook gemini` sums the new steps' `input/output/cache_read_tokens` → `to: gemini, tag: interactive`.
  - Skip sessions tandem itself started (ids already in the ledger), so nothing is counted twice.
- Dashboard headline changes from "offloaded" to **"work split"**: tokens and plan-window % per agent (interactive + delegated), and value per plan. "Offloaded" stays as a secondary stat.
- Plan usage (v0.1.x) already captures both plans' totals. Contribution = ledger, capacity = plan windows.

### E. Optional: Notion
- Mirror threads to a Notion database (one page per thread) via the Notion connector. Pros: readable on a phone, shareable. Cons: data leaves the machine, needs auth, adds latency.
- Proposal: local Conversations view first (C), Notion as an opt-in sync later (`tandem sync notion`).

### F. Effort, explained and settable
- Neon's documented default effort is `high`. The "Extra High" in the app is the app's saved setting for *your* chats. tandem's aliases use `medium` (`neon` = `gemini-4-neon-medium`). Orchestrator manages its own effort; `--effort` is ignored there (research §4).
- `tandem prefer gemini neon-high` / `--effort xhigh` per call. Bench data decides defaults (ADR 0005).

## Gemini critique: adopted changes
1. **No double counting:** tandem sets `TANDEM_MANAGED=1` on every agent it spawns, and both Stop hooks exit immediately when they see it.
2. **No self-review:** categories `review`, `plan-critique` and `second-opinion` are `partnerRequired`. `route(task, budget, lead)` always returns the *other* agent for them.
3. **Cheap Claude calls when Gemini leads:** one Claude session per thread (`--resume`, warm cache). Gemini's skills batch critiques and send diffs or summaries, never file dumps. `ask_claude` gets routed defaults (Sonnet unless the task needs Opus).
4. **Transcripts:** store `transcriptPath` + session id only. Read `transcript.jsonl`, falling back to `transcript_full.jsonl` when fields are truncated. No prompt copies (resolves the old decision #1).
5. **Threads default to the MCP server session** (an agent can pass its own). `init --global` removes v0.1 loose files when it installs the Antigravity plugin.
6. **New pattern, handoff-lead:** pass the lead role and a thread summary when the work shifts (e.g. Gemini's broad exploration → Claude's architecture decision).
7. `orchestrator` is described everywhere as "a Gemini model (Neon plans, Hydrogen executes)", never as the team lead. The dashboard shows plan-usage freshness.

Principle kept from the critique: **equal control ≠ equal spend.** Either agent can lead, but Claude's calls stay surgical because Claude's plan window is the scarcer one.
