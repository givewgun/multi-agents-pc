# 0009. Budgets are plan windows, not dollars

Date: 2026-11-23 · Status: accepted (supersedes the budget part of 0006)

**Context:** Both agents are flat-rate subscriptions metered by rolling windows (5-hour + weekly), not by API dollars. v0.1 budgeted Claude in API-equivalent USD/week and Gemini by call counts, which says nothing about how close a plan is to its limit. Verified: `claude -p --output-format stream-json --verbose` emits `rate_limit_event.rate_limit_info.unifiedWindows.{five_hour,seven_day}.{utilization,resetsAt}` with every call. `agy -p /usage --output-format json` returns `command.data.groups[].buckets[]{window: 5h|weekly, remaining_fraction, reset_time}` for free (0 tokens). Claude has no free equivalent: `claude -p /usage` is sent to the model and billed.
**Decision:** `src/usage.js` keeps the latest snapshot per agent in `~/.tandem/usage.json`. Gemini refreshes whenever it's older than 5 min. Claude is captured from every Claude call tandem makes, or from an explicit `tandem usage --refresh-claude` (a ~$0.006 Haiku ping). Windows past `resetsAt` read as 0. Limits are fractions of each window (`budgets.claude5h` 0.8, `claudeWeek` 0.85, `gemini5h`/`geminiWeek` 0.95, `warnAt` 0.7 × limit). Claude's are lower to leave room for interactive Claude Code use. The router reroutes when an agent's window is at its limit or its status is `rejected`; a Gemini quota error in the last 5h also counts. Dollars stay as information only ("value offloaded").
**Consequences:** + budgets match what actually runs out, including usage outside tandem (both readings are plan-wide). − Claude's reading goes stale between Claude calls; age is shown. Old config keys (`claudeWeeklyUsd`, `gemini5hCalls`, `geminiWeeklyCalls`) are ignored.
